Architecture proposal

AgentForge

A continuously running multi-agent red team for the OpenEMR Clinical Co-Pilot.
Seven decisions, the alternatives we weighed, and what each one costs us.

What it must do

  • Generate and mutate attacks, including multi-turn
  • Judge success consistently across target versions
  • Turn confirmed exploits into regression tests
  • Write reports an engineer can act on unaided
  • Decide what to test next, and stop when cost buys no signal

Hard facts shaping the design

  • Target: TypeScript on Railway, REST/JSON, uploads land in OpenEMR
  • One shared Anthropic bill, keep cost as low as possible
  • No open-weight provider budget, no local models, no GPU
  • Langfuse self-hosted, as in Phases 1–2
  • All patient data synthetic; canaries allowed

The shape

Four agents, four trust planes, one deterministic core

LLMs only where judgement is needed. Everything that must be exact is ordinary tested code. Runs once a night plus an operator queue; managed from a dashboard.

OrchestratorBuilds tonight's plan: reruns, owed regressions, then coverage gaps. Answers the dashboard chat. Never touches the target.
Red TeamDeterministic mutation floor + Haiku variants + Sonnet strategy. Least trusted. Target via adapter only.
JudgeDetectors first (authoritative), then frozen-rubric Sonnet, Opus tiebreak. Calibrated nightly.
DocumentationSchema-validated, deduplicated reports. Drafts only; humans publish high/critical.
Target AdapterOnly network path to Co-Pilot and OpenEMR. Allowlist, rate limits, budgets, transcripts.
DetectorsPHI canaries, cross-patient, tool-log diff, scope rules. No vendor in the loop.
Regression HarnessReplays exploit families against every new target version.
Postgres + DashboardExploits as tickets, nightly queue, checkpoints, event log. Dashboard renders all of it and takes operator actions.
Rejected: single agent or linear pipeline. Attack generation and evaluation in one context is a conflict of interest by design, and prioritization is a different job from execution.

Decision 2

Claude attacker on a deterministic floor, OpenRouter added Thursday

Haiku 4.5 for variants, Sonnet 5.5 once per campaign for strategy, refusals detected and counted per technique. Thursday, when budget allows, an open-weight tier via OpenRouter goes only where Claude declines.

Chosen

  • No new account or budget line; same bill and SDK
  • Authorized testing of our own app; Claude generally assists
  • Refusal rate tracked per technique so gaps are visible
  • Deterministic operators carry most of the volume anyway

Alternatives

  • Hosted open-weight via OpenRouter: no refusals, different vendor from the Judge, separate rate-limit pool. Added Thursday, time-boxed to two hours, feature-flagged, go/no-go on Wednesday's run being stable. Router seam built Monday so it is a config change.
  • Local model: ruled out, nothing runs locally.
  • Deterministic only: never novel.
Cost of this choice: through Wednesday, attacker and Judge share a vendor, so independence rests on vendor-free detectors being authoritative, separate models and contexts, and nightly ground-truth calibration. Thursday's tier restores vendor separation where it matters, and Friday reports refusal rates with and without it.

Decision 3

Hybrid Judge: detectors rule, LLM fills the gaps

Exact where exactness is possible. Semantic only where needed. Continuously validated.

How a verdict is made

  • Stage 1 detectors: PHI canary, cross-patient, tool-log diff, scope rules. Fire = success, confidence 1.0.
  • Stage 2 Sonnet with a frozen, hashed rubric and structured output; rubric hash stored on every verdict.
  • Stage 3 Opus tiebreak on low confidence or disagreement; still unsure = human queue.

Keeping it honest

  • Labeled ground-truth set, re-judged nightly and on every rubric change
  • CI invariants: never fail when a detector fired; never success on clean controls; same transcript, same verdict
  • Drift alert on agreement drop or clean-control success; fix is a new rubric version, never a silent edit
Rejected: LLM-only (expensive, drifts, cannot be sole authority on PHI); deterministic-only (misses partial success); same model as attacker (conflict of interest).

Decision 4

A regression test passes only when the family is blocked

"The model stopped responding to that exact phrasing" is not a fix.

Pass requires all four

  • Minimal reproduction is blocked
  • Every stored successful variant is blocked
  • Fresh deterministic mutations are blocked
  • Clean control still gets a helpful answer (no over-blocking)

Replayed 3× against a non-deterministic target; majority rules and the flakiness is recorded, not hidden.

Also caught

  • Per-category pass rate compared across versions, so fixing one thing that breaks another is flagged
  • Minimal repro derived by delta-debugging and re-verified before the report is written
Rejected: replay the exact sequence once. Cheapest, and worse than no test.

Decision 5

Humans gate what is expensive to get wrong. Nothing else.

Decision 6

Typed contracts persisted in Postgres, not an in-memory bus

Every hand-off is a versioned JSON Schema in /contracts, validated by Ajv on both sides, stored as a row.

Why

  • Replayable and auditable: reconstruct an overnight run from a trace ID
  • Agents are independently testable and swappable through the schema alone
  • Typed errors for every known failure (target unreachable, budget exceeded, judge timeout, refusal, regression detected)
  • One Postgres for exploits, queue, checkpoints, and event log

Alternatives

  • In-process calls only: fastest, no durable per-message audit trail
  • Redis / RabbitMQ / SQS: a second system to deploy and secure this week; revisit at 10K+ runs
  • SQLite: no roles, weak concurrency; local dev only
8 / 10
Decision 7

Self-hosted Langfuse on Railway, instrumenting the target too

Chosen

  • Matches the Phase 1–2 decision and the healthcare context
  • On Railway so the Co-Pilot can reach it; a laptop instance could not be
  • Co-Pilot gets its own Anthropic key and the same Langfuse project, so target spend appears next to platform spend
  • Per-role API keys: cost and rate-limit pressure attributable per agent on one shared bill

Alternatives

  • Langfuse Cloud: zero setup, same SDK; fallback only if self-hosting slips past Tuesday morning
  • LangSmith: proprietary, data residency questions
  • Braintrust: eval-centric, another vendor
  • Custom only: rebuilding a trace UI in a week is wasted effort
Cost is controlled structurally: detectors before LLM judge, cached rubric, Batch API for regression verdicts, novelty fingerprints so duplicates never hit the target, per-campaign budget envelopes with a signal-per-dollar halt. The target's own model calls remain the largest line.

Decision 8

Nightly runs, a ticket tracker, and a chat box to the Orchestrator

Not a continuous loop. One run a night inside a budget envelope, an operator queue that feeds it, and a dashboard that is the product surface.

Operator Dashboard

  • Findings as tickets: severity, category, OWASP, status, assignee, evidence, repro, history. Re-check tonight queues the exploit family for the next run.
  • Tonight's queue in the order the Orchestrator will take it, with estimated cost and what gets cut.
  • Run history and the morning report; coverage heatmap; resilience trend; cost per role and for the target; Judge health; live agent activity; approvals.
  • Chat with the Orchestrator: ask why, queue reruns, set focus, skip a category. Every directive is echoed, confirmed, typed, and logged.

Alternatives

  • Continuous loop: fastest on deploys, but spend is bounded only by envelopes and it competes with daytime Co-Pilot traffic on the shared rate limit. Deploys now queue a regression for tonight; Run now covers urgency and demos.
  • GitHub Issues or Linear as tracker: familiar, but two-way sync of status and evidence is its own project and the rerun button becomes a webhook hack.
  • Forms only, no chat: cannot answer "why did you choose X". Kept alongside chat for every action.
  • Chat with unrestricted actions: a bypass for every human gate. Rejected.
Trade-off: up to a day between a deploy and its regression run unless someone presses Run now. React dashboard on TanStack Start, Router, Query, Table, and Form shares the data layer with the worker; tickets are the exploit records, not a second system.
